# 運用ガイド

## 起動と初回設定

通常はWindows同梱版のZIPをすべて展開し、`GijiAutoMemo.exe` をダブルクリックします。EXEのそばにある `_internal` と `models` は移動・削除しないでください。Python、Node.js、Git、標準の音声モデルを別にインストールする必要はありません。[Windows配布ガイド](distribution.md)

Outlook（クラシック）を同じWindowsユーザーで起動しておきます。設定画面でOutlookの予定を同期し、Teamsで使う録音デバイスを選び、手持ちのLLM APIキーと送信先・モデルを設定してください。標準の予定連携にはMicrosoftのアプリ登録やAPIキーを使いません。

録音前に参加者への案内と必要な同意を済ませ、設定画面の録音・外部送信の確認項目を読んでください。自動録音は初期状態では無効です。

起動時のコンソールを開いたまま使います。ブラウザーのタブを閉じてもバックエンドが動いていれば処理は続きます。EXEをもう一度起動すると既存のホーム画面を開き直します。終了はコンソールで `Ctrl+C`。録音中は先にアプリで録音を停止してください。

EXEは未署名です。組織の実行制限がある場合は、その配布・実行手順に従ってください。アプリ側で保護機能や管理ポリシーを変更することはありません。

## 最初の実機確認

本番会議の前に、同意済みの相手との短いテスト会議で両方の音声を確認してください。録音開始表示だけでは、正しい出力デバイスが選ばれていることまで確認できません。

1. Teamsのデバイス設定と、このアプリのマイク・再生デバイスを合わせる。
2. アプリ側で録音を開始し、自分と相手が交互に話す。
3. 録音を停止して、それぞれの音声を再生する。
4. 同梱モデルで文字起こしと話者ラベルを確認する。
5. 自動録音を有効にして、参加・退出による状態遷移を確認する。

録音停止後に会議一覧へ戻っても処理は続きます。次の会議は録音できますが、文字起こし・議事録生成はキューで順番に処理します。処理時間は会議の長さとPC性能によって変わります。

## 状態の読み方

| 状態 | 意味 |
| --- | --- |
| 録音中 | マイクと再生デバイスの音を保存中 |
| 文字起こし中 | 保存した音声をローカルモデルで認識中。前の会議の処理待ちを含む |
| 話者分離中 | 相手側の音声を話者ラベルへ割当中 |
| 議事録生成中 | 設定したLLMへ文字起こしを送り、構造化された議事録を生成中 |
| 完了 | 処理が完了した状態 |
| エラー | 設定、音声、モデル、ネット接続などの確認が必要。途中の文字起こしは残る場合あり |
| 中断 | 前回のアプリ終了などで処理が止まった状態。保存済み音声から再処理可能 |

録音中にアプリを終了すると、保存できた音声を残して中断状態にします。次回起動時に自動でLLMへ再送せず、ユーザーが再処理を実行します。強制終了やPC障害では最後の音声が欠けたりWAVが不完全になったりする可能性があります。

生成中に終了すると、実行中のモデル推論やAPI要求が戻るまでプロセスが残る場合があります。強制終了した処理は、次回起動時に状態を確認して再処理してください。

## 自動終了と会議の延長

Teamsの参加状態は約2秒ごとに確認します。退出状態が標準で12秒間続くと録音を停止して処理を開始します。読み取り不能・検知不明の間は終了と判断しません。

- 予定時刻を超えても、参加中なら継続します。
- 予定より早く退出したら、その退出状態で停止します。
- 短い画面切替や再接続で退出状態が解消すると、終了の猶予をやり直します。
- 一度手動停止した同じ通話を直ちに自動録音し直すことはありません。退出の確認後、次の参加を待ちます。
- 長い切断や退出後の再参加は別セッションになる場合があります。
- 「自分が退出した」ことを終了と扱います。他の参加者全員が退出するまで待つものではありません。
- Teams上のミュートはローカルマイク録音の停止とは異なります。録音したくない会話はアプリで停止してください。

会議一覧の件名とTeamsの参加状態の対応付けは完全ではありません。アプリから会議の参加操作をすると、その会議を優先します。同時刻に候補が複数あって特定できない場合は、特定の予定に決めつけず録音を保存します。

## Outlookの予定同期

標準ではOutlook（クラシック）の既定予定表を60秒ごとに読み取ります。アプリ側の同期とは別に、Outlookが最新の予定を受信している必要があります。「新しいOutlook」やブラウザー版だけを起動しても、この連携は利用できません。

読み取り時にOutlookのプロファイル選択・サインイン・セキュリティ確認が表示される場合があります。予定取得は独立した補助プロセスで実行し、応答がない場合は同期状態にエラーを出します。アプリはOutlookの保護設定を変更しません。[Outlook連携の設定](microsoft-setup.md)

## 保存先とバックアップ

標準の利用データ保存先は `%LOCALAPPDATA%\giji-automemo` です。

```text
giji-automemo/
  giji.sqlite3          設定・会議・セッション・文字起こし・議事録
  recordings/
    <session-id>/
      microphone.wav   マイク音声
      system.wav       再生デバイスの音声
  models/              追加取得・変更した音声モデル
```

Windows同梱版の標準モデルは、展開したアプリフォルダーの `models` から読み取ります。追加取得したモデルは上の利用データ側に保存されます。同梱モデルを使うために利用データ側へコピーする必要はありません。

LLM APIキーはWindowsの資格情報ストアに保存されます。任意のGraph連携を使う場合のみ、その認証キャッシュも同じストアを使います。SQLiteに平文で書く代替動作はしません。標準のOutlookデスクトップ連携では、Microsoftの認証情報をアプリに保存しません。

バックアップはアプリを終了してから利用データフォルダーをコピーします。別PCへ移す場合は、そのPCのOutlookプロファイルとLLM APIキーを設定してください。音声と文字起こしは通常のローカルファイルであり、アプリが独自暗号化するものではありません。

セッションの削除は録音ファイルとその記録を削除します。録音中・処理中の削除はできません。モデルは複数セッションで共用します。手動でデータフォルダーを消す場合は、必要な議事録を先に書き出してください。

## よくある問題

| 症状 | 対応 |
| --- | --- |
| EXEを起動しても画面が開かない | ZIPが完全に展開され、`_internal` がそろっているか。コンソールに表示された内容と組織の実行制限を確認 |
| Outlookの予定を取得できない | クラシック版・サインイン済みのプロファイル・同じWindowsユーザーを確認。Outlookの確認画面も確認 |
| 相手の音量が0のまま | Teamsのスピーカー出力とアプリのループバック対象を一致させる。ヘッドセットの「通話」と「ステレオ」が別デバイスの場合にも注意 |
| 自分の音量が0のまま | Windowsのマイク許可、物理ミュート、選択したマイクを確認 |
| デバイス変更後にエラー | 保存済みの部分音声を確認。デバイスを再選択して新しく録音 |
| Teams状態が不明 | Teams会議ウィンドウを表示。改善しない場合は手動開始・停止。Teams更新で内部IDが変わる場合あり |
| 自動開始しない | 自動録音と録音確認を有効化。Teamsデスクトップ版か確認。状態が不明なら手動で録音 |
| 同梱版なのにモデル未準備になる | EXEと同じ場所に `models` があるか。標準の `small` 以外を選んでいないか。欠落があればZIPを展開し直す |
| 音声認識が遅い | CPU負荷と空きメモリを確認。小さいモデルへ変更する場合は、そのモデルの追加取得が必要 |
| 話者が混ざる | ヘッドセットを使用。別人が同じラベルになる場合や一人が複数ラベルになる場合があるため、音声と照合して名前を編集 |
| 誤った名前が議事録にある | 話者ラベルに実名を手動設定。担当者や期限は原文と照合 |
| LLMがエラー | APIキー、ベースURL、モデルの利用権、利用限度、外部送信設定を確認して再処理 |
| 追加モデル取得が失敗 | GitHub/Hugging Faceへの接続と空き容量を確認し、設定画面から再実行 |
| 接続URLの認証が切れた | EXEを起動し直してホームを開く。アプリ再起動前のURLは使用しない |

キー未設定・外部送信OFFの場合も、ローカル文字起こしまでは保存されます。議事録生成段階のエラー案内を確認し、設定後に再処理してください。

APIキー・認証トークン・実際の文字起こしをGitHub Issueへ貼らないでください。再現手順、Windows/Teams/Outlookのバージョン、公開してよいエラーメッセージで報告できます。

## 毎日の起動と更新

通常は `GijiAutoMemo.exe` を起動します。必要ならWindowsのスタートアップフォルダーに、そのEXEへのショートカットを作成できます。初期状態でOSの自動起動設定は変更しません。アプリを使わないときやPCがスリープ中は、予定同期と録音は実行されません。

更新時は録音と処理を終えてアプリを終了し、新しいZIPを別フォルダーへすべて展開してください。通常の利用データは `%LOCALAPPDATA%` にあるため、EXEの展開先とは分かれています。更新前には利用データをバックアップしてください。

## 起動オプション

必要な場合だけ、PowerShellからEXEにオプションを付けます。

```powershell
# デモデータを追加して起動
.\GijiAutoMemo.exe --demo

# 利用データの保存先を変更
.\GijiAutoMemo.exe --data-dir "D:\GijiData"

# 使用ポートを指定（標準は空いているポートを自動選択）
.\GijiAutoMemo.exe --port 8765
```

ソース版ではEXEの代わりに `.\.venv\Scripts\python.exe -m giji` を使います。

同じ保存先を使うアプリの二重起動はロックします。起動中は保存先の `launch-url.txt` に認証トークン付きURLを保持します。開発・診断用の `--no-browser` はブラウザーの自動起動を省略します。URLは自分のPCのブラウザーでのみ使用し、ファイル内容やURLを共有しないでください。ファイルは終了時に削除します。
