# 検証結果

v0.4のTeamsデスクトップ連携はプレビューです。実装済みと実機検証済みを区別し、過去版の確認結果も版ごとに記載しています。

## v0.4：この開発環境で確認したこと

- UIA読取りの単体テスト49件成功。合成した画面ツリーとWindows APIの代替実装を使い、
  最小化・非表示の判定、所有者確認、選択中カレンダーの検証、明示的な非表示要素の除外を確認。
- CDPの単体テスト50件成功。加えて、実Chromiumに合成ページを読み込ませる14件のテストが成功。
  Teams配下を模したカレンダー別ウィンドウ、読込み済みの画面外要素、非表示キャッシュの除外を確認。
  実際のTeamsの画面やアカウントを使う検証ではありません。
- TypeScriptチェックとVite本番ビルドが成功。
- ブラウザーのAPIフィクスチャで、予定取得の成功 → 失敗 → 再試行 → 復旧を確認。
  保存済み予定が残る場合もエラー状態と最終読取り時刻を区別し、JavaScript例外は0件。
- 実バックエンドをLinuxで起動し、デモの一覧・議事録・文字起こし、話者名編集、
  Markdown書き出し、設定保存、デモ削除と390px幅の画面をChromiumで確認。
  ホーム・議事録・設定のスクリーンショットはこのv0.4デモ実行から更新しました。

Python全体のテストとPython 3.13での全体結果は集計待ちです。上の個別件数を全体の件数として
扱わず、完了後に実行環境と結果を追記します。

## 利用するWindows PCで必要な確認

- Outlookを必要とせずTeamsに接続し、今日の予定を読み取れること。日本語・英語、
  Teams内のカレンダーiframe、画面切替・仮想スクロール、予定変更・取消の確認が必要です。
- 標準UI Automationで接続準備・Teams再起動・レジストリ変更なしに読み取れること。
  WindowsとTeamsのタイムゾーン、最小化・トレイ格納を分けた読取可否、補助プロセスの終了も確認が必要です。
- 任意のCDP方式で、一時設定の復元、準備の期限切れ、アプリ再起動後の再準備、
  解除後のTeams通常再起動でデバッグ接続が閉じること。会社の管理ポリシー下での動作も未確認です。
- Windows 11、利用中のTeams版、ヘッドセットでのUIA検知とWASAPI録音。
- Teamsを最小化・トレイ格納した場合の状態と情報の保持、復元・前面化をしないこと。
- 会議の延長・短縮、退出・再参加の実動作。
- 使用するLLM APIキー・モデルでの議事録生成。
- 使用する会社PCで、未署名の配布EXEを起動できること。
- 任意のGraph連携を選ぶ場合だけ、Microsoft 365テナントの認証・権限・予定取得。
- 任意のOutlook連携を選ぶ場合だけ、クラシックOutlookのプロファイル・予定・定期開催回・
  変更・取消とObject Model Guardの確認。

実アカウント・Windows端末・ヘッドセット・実APIキーはこの開発環境にないため、
上記の実機検証は行っていません。手順は[実機確認項目](acceptance.md)にあります。
GitHub ActionsのWindowsジョブもハードウェアやTeamsの実会議を検証するものではありません。
