# 検証結果

v0.5のTeamsデスクトップ連携はプレビューです。実装済みと実機検証済みを区別し、過去版の確認結果も版ごとに記載しています。

## v0.5：FFmpegを除いた構成

FFmpegを直接・間接・同梱ライブラリ経由でも利用しない条件に合わせ、文字起こしを
sherpa-onnx 1.13.8のWhisper ONNXへ変更しました。音声の読込みはPCM16 WAVと
Python標準ライブラリ・NumPy・SciPyを使い、画面の再生もPCMを直接扱う方式へ変更しました。
PyAV・faster-whisper・FFmpegのバイナリと対応ソースアーカイブを配布対象から除外しました。
確認済みの結果は以下です。会社PCでの実Teams・録音デバイスの確認とは区別しています。

- FFmpeg関連パッケージを入れない新しいPython 3.13環境で全体テスト **453件成功・6件スキップ**。
  スキップはWindows専用と任意のChromium検証で、Starlette由来の既存警告が1件あります。Ruffも成功。
- 同環境で公開英語音声を使い、45.25秒・44.1kHz・ステレオWAVから文字起こしを実行。
  30秒の無音を挟んだ発話時刻を保持し、無音マイクは発話なし。Whisper tinyを使った動作確認で、
  日本語・多数話者の精度評価ではありません。禁止パッケージの未導入・未インポートも確認。
- モデル取得時の固定revision・SHA-256検証、旧モデルの再利用防止、PCM16読込み、
  VAD・28秒以内への分割、元の録音時刻・発言区間に基づく話者割当を自動テスト。
- PCM再生のNodeテスト15件、TypeScript・本番ビルド成功。Chromiumの合成音声で
  再生・一時停止・1時間位置へのシーク・終端・再開・画面破棄・390px幅を確認。
  90分の仮想録音でも最初の情報取得は44バイト、各取得は最大1MiB、待機バッファは最大3個。
  メディア要素・decodeAudioDataをテストで禁止しても再生が成功し、呼出しは0件。
  旧turboモデルの未対応表示と明示切替も確認。JavaScript例外0件。
  [PCM再生の合成画面テスト](screenshots/pcm-playback.png)は実際の会議録音の画像ではありません。
- 新しいPython環境の依存検査は50パッケージ・146ネイティブバイナリで成功。
  禁止名を変更したPE依存、遅延インポート、内包アーカイブの検出も自動テストしています。
- sherpa-onnx 1.13.8のWindows wheelのSHA・PE依存と上流ソースを確認。
  対象と限界は[音声処理の依存関係](audio-dependencies.md)に記載しています。

- 使用する会社PCで、未署名の配布EXEを起動できること。
- 任意のGraph連携を選ぶ場合だけ、Microsoft 365テナントの認証・権限・予定取得。
- 任意のOutlook連携を選ぶ場合だけ、クラシックOutlookのプロファイル・予定・定期開催回・
  変更・取消とObject Model Guardの確認。

実アカウント・Windows端末・ヘッドセット・実APIキーはこの開発環境にないため、
上記の実機検証は行っていません。手順は[実機確認項目](acceptance.md)にあります。
GitHub ActionsのWindowsジョブもハードウェアやTeamsの実会議を検証するものではありません。
